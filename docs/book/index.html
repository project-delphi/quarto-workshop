Prompt, Check, Publish

Reproducible Data Publishing with Quarto and AI Coding Assistants

A practitioner’s guide to reproducible publishing: write once in Markdown, let a coding assistant write the code, check its work, and rebuild one source into a web page, Word, PDF, slides, an e-book, a website, a blog and a dashboard. Two real projects run through the book: a London visitor guide and a study of drinking-water risk in Colombian municipalities.

Preface: How to Use This Book

Change one number in a dataset, and how many documents are now wrong? If the number was copied by hand into a report, a slide, an email and a web page, nobody knows without searching. This book teaches a way of publishing with nothing to search for: you write once, in plain text, and a web page, a Word document, a PDF, slides, an e-book, a website, a blog and a dashboard all rebuild from that one source with one command. The program that rebuilds them is Quarto.

Quarto is one of three parts. With git, which records every version of the source, and a hosting service such as GitHub Pages, which puts the result on the web, it lets one person produce reproducible, publication-quality work for a wide range of settings and formats: a page read on a phone, a report printed for a meeting, slides on a projector, an e-book, an interactive dashboard. Coding assistants speed all of it up. The cryptic commands and fragile configuration that used to stand between an analysis and its published, interactive form are no longer the bottleneck: you describe the step, the assistant writes the commands, and you check the result.

Prompt, Check, Publish

The title names the method, a loop you run at every step of both projects. You prompt a coding assistant, a program that writes files and runs commands at your request, describing one small piece of work with its files and columns named. You check what it did: read what changed, look at the result, compare it with the data. An assistant can be fluent, fast and wrong, so this step is never skipped, and it is always yours. Then Quarto publishes, rebuilding every output from the checked source the same way every time. Chapter 1 explains why the last step can be trusted, and Chapter 2 how to make the first two reliable.

Who this book is for

I wrote this book for researchers, software practitioners, data experts and students: anyone who works with data/code and needs to share the results. It shows how to publish from one source of plain-text file (prose & code), using Quarto. Quarto is free and open source traditional software, so every report, slide deck and web page is reproducible, interactive and of publication quality. With a coding assistant, work that once took days now takes minutes. Along the way, I explain the concepts, arguments and decisions behind each step.

Reproducibility is why I wrote this book. Work that others can rebuild earns their trust, justifies the decisions made on it, and gives them something to build on, which is how science, technology and understanding move forward. More automation means fewer errors and a better experience, for the people who make the work and for those who read it.

Publishing is half the job; the other half is being read. Content works only if it engages the people it is for, so the book treats every output as something a particular reader will use, and checks it as that reader would. My hope is that it improves the interactions, and the outcomes, of everyone who works with data, software and AI applications and has to communicate them.

You may be new to Quarto, to coding assistants or to both. No programming is assumed: I explain the Python the assistant writes, but you do not have to write it. If the terminal is new to you, Chapter 3 teaches the little you need, one checked step at a time.

You will need a computer on which you can install software (Windows, Mac or Linux), a free GitHub account, and an account with one coding assistant (Before you start lists what each needs).

The two running examples

Every concept is tied to one of two projects, both built on real, cited data.

A London visitor guide (Part II). For the city’s tourism office, you write one guide that becomes a web page, a Word brief for partners, a printed flyer, a dashboard for managers and a published website. Every visitor number in it, from the 7,116,929 visits to the Natural History Museum (South Kensington) in 2025 down, is computed from the counts published by the Association of Leading Visitor Attractions.

Drinking-water risk in Colombian municipalities (Part III). You group Colombia’s municipal zones into kinds by water safety, services and context, from 2016 to 2023, compare health and education outcomes between the kinds, and publish the analysis as a report, slides, a blog post and a website, all from one analysis script. Most of the data are Colombian open data, joined by official municipality codes; rainfall comes from the Climate Hazards Center’s CHIRPS data and altitude from NASA’s SRTM elevation data (Appendix G — Data Sources, Licences and Credits).

How the book is organised

Part I covers what you need first: what Quarto does (1  Publishing That Rebuilds Itself), how to work with a coding assistant safely (2  Working With a Coding Assistant) and how to set up your computer (3  Setting Up Your Machine). The GitHub account it asks for is free; an assistant’s account may not be. Claude Code, for one, needs a paid plan or pay-per-use billing (checked 2026-11-03; Before you start lists what each assistant needs). Parts II and III build the two projects, with the statistics explained on the way, and each ends by changing an input and explaining what the rebuild changed. The appendices hold the Windows setup, a cheatsheet, troubleshooting, every checkpoint, the data sources and how this book is built.

By the end of the book you will be able to:

  • explain how Quarto turns one source into many formats, and why every rebuild gives the same result;
  • direct a coding assistant safely: a folder of its own, written rules, and one step per prompt, each ending in a check;
  • build and publish both projects, the London guide and the water-risk website, each in several formats;
  • predict which outputs a changed input will update, and check that the rebuild did exactly that.

Each step is a three-part box, explained in How to read the assistant boxes: the exact prompt to give your assistant, what it will probably run, and the few things only you can do. Two ways through

Self-paced. Read in order. Chapters 2 and 3 can be read and done in one sitting before Part II; each chapter of Parts II and III ends at a checkpoint or at the finished example, where you can stop and resume later.

Workshop-paced. The book grew out of a six-hour workshop and keeps its shape, while explaining what the workshop only had time to show: why each step works, where it fails, and when not to take it. Appendix I — Running This as a Workshop has the day’s agenda and the chapters each block covers (Table I.1 and Table I.2).

When you get stuck

You will get stuck: an install fails, a prompt goes wrong, a render stops with an error you have never seen. That is expected, and the book is built for it. Every hands-on block ends at a checkpoint, a folder in the workshop’s repository (checkpoints/), the copy of the workshop’s files you download during setup (Step 5: Run the setup check). It holds the project as it should be at that point, with a README listing the steps to catch up. The rule is simple: stuck for two minutes, catch up. Where the book reaches a checkpoint, a catch-up box gives the one line to paste into your assistant (Figure 2).

The README’s last step names the workshop slide to rejoin at. In the book, that place is the catch-up box itself, so after catching up you carry on reading from the box. If you were stuck partway through a block, go straight to its box: the checkpoint already holds the steps between where you stopped and the box. Appendix E — Checkpoints at a Glance, and Answers lists every checkpoint.

Two editions

This book comes as an e-book (EPUB) and as a website, built from the same source: it is its own first example of the method. The website edition runs everything interactive: the 3-D scenes of the London map, the k-means steps, the clusters and Colombia’s relief, and two data explorers. The e-book shows each as an animation or a still, with a link to the live version (the first, the London map, also has a QR code). Readers that cannot play animations show the first frame, designed as a useful still, and the website respects your reduced-motion setting.

Versions and dates

The book was built and checked with Quarto 1.10.20 (with its bundled Typst 0.15), Python 3.12 and uv, in November 2026. Facts that change, such as a model’s price, an assistant’s screens or a free hosting plan’s limits, carry the date they were checked, as in “(checked 2026-11-06)”. Some will have changed by the time you read them; the principles around them should not have.
